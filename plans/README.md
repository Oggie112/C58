## Recommended execution order

**1 → 6 → 7 → 003 → 002 → 004 → 005 → 008 → 009**

- **001** is fully independent of everything else (different files: CTA buttons). Run it first/anytime.
- **006 → 007**, in that order: both touch `NavClient.tsx` (006 edits the header/hamburger transition props at lines 28-32 and 63-65; 007 edits the imports, adds a hook call, and replaces the overlay block at lines 70-84). Disjoint line ranges, low conflict risk, but running 006 first avoids the executor re-locating shifted line numbers for 007's later edits.
- **003, 002, 004, 005, 008, 009** all touch `EventListClient.tsx` (002 also touches `HeroClient.tsx`, `TeamBlock.tsx`, `VolunteerBlock.tsx`, `TalentListClient.tsx`; 003, 004, 005 touch the same four non-EventListClient files too). Run them **in this order**:
  1. **003** first — establishes `EASE_OUT_EXPO` / `--ease-out-cubic` so later plans' code stays clean, though each plan also works if 003 hasn't run yet (they cite the current inline literal as a fallback).
  2. **002** next — adds `useReducedMotion()` wiring and turns `EventListClient`'s `CARD_VARIANTS` into a component-local `cardVariants`.
  3. **004** next — adjusts the `delay` expression in the same variant objects 002 just touched.
  4. **005** next — converts `y`/`scale` shorthand to `transform` strings; explicitly skips `TalentListClient.tsx` (incompatible with its `layout` FLIP animation — see plan 005's Boundaries).
  5. **008** next — adds the `TAB_EASE` constant and rewrites the tab switcher block (lines 43-58, above everything 002-005 touch).
  6. **009** last — wraps the empty-state message (lines 61-66, below the tab switcher) in a fade; textually last in the file, so it's least disrupted by earlier edits.

If running plans out of this order or via parallel isolated-worktree executors, each plan's own file notes how to locate its target code even if an earlier plan in this list has already changed the surrounding lines.

## Dependencies

- None are hard blockers — every plan is self-contained per its own file. The ordering above is to minimize line-number drift and rework, not because any plan strictly requires another to have run first.
- Plan 008 introduces a second easing curve (`TAB_EASE`, ease-in-out) alongside plan 003's `EASE_OUT_EXPO` (ease-out) — this is deliberate, not a duplication to consolidate; they serve different motion types per AUDIT.md §2's decision order (entering/exiting vs. moving/morphing on screen).
